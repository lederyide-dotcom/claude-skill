# 反待辦清單（AI 做的事／人做的事）

目的：讓使用者只做人該做的事。重複、搬資料、對資料、找資料的工作，不是「請 AI 幫忙做這一次」，而是讓 AI 做出一個以後都不用人做的工具或流程。

思路來源：Felix Rieseberg（往上提一層抽象）與 Claire Vo（anti-to-do list）。

## 何時用

- 使用者說：反待辦清單、盤點工作、哪些可以交給 AI、AI 最大化、這件事好煩、又要手動做一次
- 使用者描述一件重複做第三次以上的事
- 每週或每月回顧時

## 流程

### 1. 盤點

請使用者一次倒出最近兩週實際花時間的事，不用整理。已有清單（追蹤板、週報、行事曆）就直接讀，不要叫使用者重打。

### 2. 分類

每一項分到三欄之一：

| 欄位 | 判斷標準 |
|---|---|
| **AI 做** | 重複三次以上；主要是搬、對、找、轉格式、彙整；結果可以自動驗證 |
| **人機協作** | AI 出草稿或選項，人做取捨；或結果需要人看過才能對外 |
| **人做** | 定目標與優先序、專業判斷與取捨、對外承諾、簽核與責任歸屬、人際關係、最終驗收 |

分不清時問一句：「這件事出錯，責任在誰？能不能自動檢查出來？」責任在人且無法自動檢查的，留在人做或人機協作。

### 3. 把「AI 做」的每一項往上提一層

逐項回答五個問題：

1. **整個流程是什麼**：不是這一步，而是從原始資料到最終成果的全程。
2. **原始資料在哪**：整包交出去（資料夾、信箱、既有表格），不要先人工整理。
3. **成品是什麼形式**：腳本、可重跑的流程、排程任務、儀表板、skill；不要一次性答案。
4. **怎麼自動驗證**：測試、比對、抽樣規則；寫不出驗證方式的，降到人機協作。
5. **人還要出現在哪**：通常只剩「定目標」與「看差異或驗收」。

### 4. 輸出格式

```
# 反待辦清單｜YYYY-MM-DD

## AI 做（升級成工具或流程）
| 項目 | 現在怎麼做 | 改成什麼 | 原始資料 | 驗證方式 | 人只需 | 下一步 |

## 人機協作
| 項目 | AI 產出 | 人決定什麼 |

## 人做（不交出去）
| 項目 | 為什麼留給人 |

## 本週先做哪一項
<一項，理由一句：省下的時間最多或最容易驗證>
```

### 5. 交棒

- 選定要做的項目後，依 spec-handoff-tw 產出 spec，再交給 autonomous-dev-loop 或 dev-orchestrator-tw。
- 很小的項目（半小時內）直接做，不必寫 spec。
- 清單存放位置依使用者指定；沒指定就回覆在對話中，並問一次要不要存檔。

### 6. 回顧

更新清單時，先看上次「AI 做」的項目是否真的不用人做了。還在手動做的，找出卡在哪（資料拿不到、驗證寫不出來、成品不好用），再決定修或降級。

## 守則

- 一次只推一到兩項，做完再加；不要一口氣列二十項都不落地。
- 不確定 AI 做不做得到的，先做最小試驗再決定欄位，不要猜。
- 下列事項一律留在「人做」，除非使用者明說：寫入真實 PLC／SCADA、對外簽核與工程簽證、付費與採購、刪除原始資料、對客戶的承諾。
- 模型選擇看問題界定程度：範圍清楚用較快的模型，需要一起定義問題才用最強的模型。
- AI 產出要誠實標示：模擬值、假設值、未查證的地方明確寫出。

## 可直接用的提示

**盤點**
```
這是我最近兩週做的事（未整理）：<貼上>。依 anti-todo-tw 分成 AI 做／人機協作／人做三欄，並建議本週先自動化哪一項。
```

**往上提一層**
```
我現在每<頻率>手動做<事情>，步驟是<步驟>。不要幫我做這一次；請設計一個讓我以後不用做的工具或流程：全程範圍、需要的原始資料、成品形式、自動驗證方式、我還需要出現的節點。
```

**整包交付**
```
資料夾<路徑>裡是<專案>的全部原始資料，我沒有整理過。目標是<成果>。需要的數值請自己從文件裡找，找到的註明出處，找不到的列出來問我，不要猜。
```

**要成品不要答案**
```
把剛才的結果做成可重跑的<腳本／儀表板／排程任務>，資料更新時重跑即可，並附一個驗證指令。
```

**回顧**
```
這是上次的反待辦清單：<貼上或路徑>。哪些我還在手動做？各自卡在哪？更新清單。
```
